# 進捗報告メモ: 固定ゼロレイテンシルータの見込み評価

## 1. 今回の報告で言いたい結論

全CIFAR-100を対象に、画像ロード中に取得できる統計量だけで固定ルータを作り、カスケードに近い計算量まで下げる方針は、現時点では見込みがかなり薄い。

ただし、単に「色々試したが駄目だった」ではなく、必要なLOW分岐率を理論式で定め、その分岐に必要な情報がゼロレイテンシ特徴空間に存在するかを検証した。その結果、全体汎用ルータでは情報量が不足している可能性が高い。一方で、難易度がクラスに偏っているため、用途や対象クラス分布を限定した条件付きルータにはまだ見込みが残る。

## 2. 性能理論値の定式化

記号:

- `H`: 高精度モデルの計算量
- `L`: 低計算量モデルの計算量
- `r = L / H`
- `p`: LOWへ流す割合
- `1 - p`: HIGHへ流す割合

固定ルータの平均計算量:

```text
C_fixed = pL + (1 - p)H
C_fixed / H = p r + (1 - p) = 1 - p(1 - r)
削減率 = p(1 - r)
```

今回の値:

```text
H = 17.6 GFLOPs
L = 0.301 GFLOPs
r = 0.0171
```

必要なLOW率:

| 目標 | 平均計算量 | 必要LOW率 |
| --- | ---: | ---: |
| notebook記録 | 11.1146 GFLOPs | 約37.5% |
| parallel baseline | 9.5882 GFLOPs | 約46.3% |
| cascade baseline | 8.6645 GFLOPs | 約51.7% |

電力・エネルギーについても、演算あたりエネルギーが同程度と仮定すれば、平均エネルギー比は同じ形で表せる。

```text
E_fixed / E_H = 1 - p(1 - r_E)
```

ここで `r_E = E_L / E_H`。まずは `r_E ≒ r` と置けば、計算量削減率を平均エネルギー削減率の一次近似として使える。FPGA実装で実測電力が得られたら、`r` を `r_E` に置き換えればよい。

## 3. 実験結果: 見込みが薄い根拠

### 3.1 必要LOW率に対して実際の分岐率が足りない

claimableな厳密条件では、最良でもLOWへ流せる割合がかなり小さい。

代表結果:

| 条件 | 平均計算量 | 精度 | LOW数 | LOW率 |
| --- | ---: | ---: | ---: | ---: |
| strict CV系の良い候補 | 約15.2 GFLOPs | 約88.2% | 1389/10000 | 13.9% |
| LightGBM allowed-full | 15.7369 GFLOPs | 88.59% | 1077/10000 | 10.8% |
| notebook互換 full-fit記録 | 11.1146 GFLOPs | 88.95% | 3749/10000 | 37.5% |
| cascade baseline | 8.6645 GFLOPs | 88.88% | 5248/10000 | 52.5% |

notebook互換の `11.1146` は強いが、厳密な外部評価・CVでは再現できていない。現状のclaimable条件では、必要な37.5% LOWに対して10-14%程度しか安全に流せていない。

### 3.2 ゼロレイテンシ特徴の分離性能が弱い

難易度カテゴリ:

| Category | 条件 | Count |
| --- | --- | ---: |
| Easy | LOW正解, HIGH正解 | 6894 |
| Hard | LOW不正解, HIGH正解 | 2091 |
| Impossible | LOW不正解, HIGH不正解 | 794 |
| Inverse | LOW正解, HIGH不正解 | 221 |

モデル精度:

| Model | Accuracy |
| --- | ---: |
| LOW | 71.15% |
| HIGH | 89.85% |

Hardを見分ける単一特徴の最良値:

| 指標 | 最良値 |
| --- | ---: |
| Hard-vs-rest AUROC | 0.547 |
| Mutual information | 0.0081 |
| Effect size | 0.201 |

さらに、allowed-full特徴756次元を使った強いモデルでもAUCは概ね `0.53-0.56` 程度だった。これは「傾向はあるが、固定ルータとして必要な大量のLOW分岐を安全に作るほどの情報量はない」ことを示す。

### 3.3 特徴空間上の衝突がある

Hardサンプルに対して、allowed-full特徴空間で近いEasyサンプルが存在する。

| 指標 | 値 |
| --- | ---: |
| Hard samples | 2091 |
| Easy samples | 6894 |
| Hardから最近傍Easyまでの距離中央値 | 31.84 |
| 上位衝突ペアの同一クラス率 | 81.25% |

同じクラス内でも、ゼロレイテンシ統計は近いのにLOW/HIGHの必要性が異なる例がある。これは、LOWが失敗する原因が単純な画像品質だけではなく、意味的特徴やモデル内部表現に依存している可能性を示す。

## 4. 「完全に無し」ではなく条件付きでは残る理由

Hard率はクラスに偏っている。最大クラスではHard率が40.0%で、Hard全体の上位10クラスが全Hardの16.93%、上位20クラスが31.52%を占める。

これは、全体汎用ルータは難しいが、以下のような条件では可能性があることを示す。

- 対象クラス分布が既知の用途
- LOWで十分なクラス群だけを扱うモード
- 難クラスが出にくい運用条件
- 最悪遅延を固定したいリアルタイム用途
- カスケードのデータ依存レイテンシが問題になるシステム

この場合の主張は「汎用的にカスケードを超える」ではなく、「特定運用条件では、固定遅延を保ちながらHのみ実行に近い精度を維持し、平均計算量・平均エネルギーを削減できる」に変える。

## 5. 明日の説明の流れ

1. まず `H`, `L`, `p` で性能理論式を示す。
2. カスケードや過去記録に近づくにはLOW率37.5-51.7%が必要だと示す。
3. 実験では、claimable条件でLOW率10-14%程度に留まったと示す。
4. なぜ届かないかを、AUC 0.53-0.56、単一特徴AUROC 0.547、特徴衝突で説明する。
5. 結論として、全体汎用の固定画像統計ルータは見込み薄いと述べる。
6. ただしHard率がクラスに偏るので、用途・クラス分布を絞る条件付きルータに次を切る。

## 6. 想定される質問への答え

### Q. それは単に探索不足では？

A. 画像統計ルータ候補を試しただけでなく、allowed-full特徴756次元を定義し、その上で強いモデルによる上限推定を行った。それでもAUCが0.56程度で、必要LOW率に大きく届かなかった。したがって単なるモデル選択の問題ではなく、観測可能特徴に含まれる情報量の不足が疑われる。

### Q. できないなら研究としてどうするのか？

A. できない可能性自体を、必要LOW率と観測可能情報量の不一致として説明できる。また、完全撤退ではなく、クラス分布や用途条件を限定した場合の条件付き有効性を次に検証する。

### Q. カスケードに勝てないなら意味はあるのか？

A. 平均計算量だけではカスケードが強い。一方、固定ルータは最悪レイテンシが固定される。カスケードはデータ依存でLOW後にHIGHを追加実行するため、リアルタイム制約下では固定ルータの価値が残る。したがって次の比較軸は平均GFLOPsだけでなく、最悪遅延、deadline miss、平均エネルギーで見る。

### Q. 次に何をするのか？

A. クラス/用途条件付きの理論値を出す。具体的には、Hard率が低いクラス群、または運用上出現しやすいクラス分布を仮定し、その条件下で必要LOW率・精度低下・平均計算量を再計算する。

## 7. 次の実験案

次は「全体汎用」ではなく「条件付きで勝てるか」を調べる。

- クラス別Hard率から、LOW適性が高いクラス群・低いクラス群を分ける。
- クラス分布を仮定したときの理論LOW率と平均計算量を計算する。
- 難クラスを除外・低頻度化した場合に、固定ルータが過去記録やカスケードに近づくかを見る。
- 実運用の例として、対象物カテゴリが限定されるFPGA/エッジ用途を想定する。

暫定結論:

```text
全CIFAR-100汎用の固定ゼロレイテンシルータ:
  見込み薄い

クラス分布・用途条件付きの固定ゼロレイテンシルータ:
  まだ検証価値あり
```

# dual_exit_reliability_shift_003 結果整理

## 実験の目的

両側早期終了が有利になる条件を探すため、CIFAR-10の通常画像に低品質画像を混ぜたシナリオで評価した。

比較対象は次の3つ。

- finalのみ: 全画像を最後まで実行し、finalの自己確信度が十分高いものだけラベルを出す。
- 上側早期終了のみ: 途中出口で高確信度ならラベルを出し、それ以外は後段へ送る。
- 両側早期終了: 高確信度なら途中でラベルを出し、低確信度なら途中で棄却し、中間だけ後段へ送る。

評価では「ラベルを出した画像だけの精度」を99%目標にした。棄却は成功扱いではなく、良品ロスや再検査に相当するコストとして扱う。

## 実行結果

ジョブ `dual_exit_reliability_shift_003` は正常終了した。

## 解釈

両側早期終了の勝ち筋は、「通常画像を単純に高速化すること」ではなく、「低品質画像が混ざる入力から、信頼できるラベルだけを拾うこと」にある。

特に遮蔽や複合劣化では、途中出口の低確信度が「後段まで進めても信頼ラベルになりにくい」ことの実用的なサインになっている。この低確信度画像を早期に棄却すると、final実行率を下げられる。

一方で、ラベル出力率は下がる。したがって、この方式は「全画像にラベルを付けたい分類」には向かない。向いているのは、低品質・曖昧・危険な入力を無理に分類せず、信頼できるものだけを通すタスクである。

## 注意点

閾値は検証データで99%目標を満たすように選んでいる。評価データでは、多くの条件で99%を超えたが、一部では99%をわずかに下回った。

例:

- clean70_mixed_quality30 の良品ロス5%級: 98.91%

そのため、発表では「99%を保証した」と言い切るより、「99%目標で調整した場合の評価結果」と表現するのが安全である。

次の実験では、検証時の目標を99.5%や99.9%に上げる、または閾値に安全マージンを入れる必要がある。

## 次に確認すべきこと

1. 99.5%または99.9%目標で同じシナリオを再評価する。
2. ラベル出力率、良品ロス、計算量削減の3軸トレードオフ曲線を作る。
3. 低確信度帯の画像がfinalで信頼ラベルに復帰する割合を、シナリオ別に可視化する。
4. FPGA評価では、早期棄却により後段回路を止めたときの動的電力削減を理論値として計算する。

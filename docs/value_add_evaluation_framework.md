# 既存技術への付加価値として評価する

## 評価の立て直し

今回の争点は「既存の欠陥検出技術そのものを新しく作ること」ではない。
既存技術を土台として使い、そこへ提案手法またはFPGA実装が何を上乗せできるかを示すことである。

そのため、評価は次の2段に分ける。

1. 土台確認
   - 既存技術として欠陥スコアが妥当に出ているかを見る。
   - 指標: AUROC, AUPR, pixel-level score, 先行研究で使われる評価条件。
2. 付加価値確認
   - 同じ土台モデルを使ったまま、提案手法/FPGA化で運用上の指標が改善するかを見る。
   - 指標: 平均計算量、最悪/平均レイテンシ、消費電力見積もり、棄却率、良品ロス、不良誤通過、閾値安定性。

## 厳しい検品条件の扱い

`false pass <= 1%` のような条件は、既存技術の再現失敗を示すための基準ではない。
これは「検品ライン風に運用すると、どこに負荷や弱点が出るか」を見るための条件である。

例えば、Unet++/ResNet34でAUROCが高いなら、既存技術としての欠陥スコア生成はある程度できている。
一方で、低い不良誤通過率を要求すると良品通過率が落ちるなら、そこが提案手法の価値を作れる余地になる。

## 提案手法で見るべき改善

両側早期終了では、同じfinal検出器を前提にして次を比較する。

- final-only selective decision
- 通常BranchyNet型の上側早期終了
- 提案する両側早期終了
- FPGA化した場合の回路停止・パイプライン実装

主張すべき改善は「final検出器より検出性能が高い」ではなく、同じ安全条件または同等のリスク水準で次を改善できるかである。

- 後段まで流す枚数を減らせるか
- 平均計算量を減らせるか
- FPGA上で動的電力を減らせるか
- レイテンシ分布の尾を短くできるか
- 閾値や分割seedに対して安定するか

## FPGA化で追加される評価

ソフトウェア上の早期終了は、計算をスキップできてもハードウェア資源が常に存在する。
FPGAでは、分岐後に不要な後段回路をクロックゲートする、あるいは段ごとにパイプライン化することで、実際の電力・スループット指標へ落とせる。

したがってFPGA化の評価は次を含める。

- LUT/FF/DSP/BRAM使用量
- 各出口までのサイクル数
- 分岐率を掛けた期待サイクル数
- 後段回路停止による動的電力削減見積もり
- 入力分布が変わったときの分岐率と消費電力の変化

## 次の実験で必要な比較

KSDD2では、まずfinal-only baselineを既存技術として評価する。
その後、同じチェックポイントまたは同じモデルファミリを使って、提案手法が次を改善できるかを見る。

1. 同じ不良誤通過率で、良品ロスを増やしすぎず計算量を下げられるか。
2. 同じ良品通過率で、不良誤通過を悪化させず計算量を下げられるか。
3. 同じselective riskで、final-only selective classificationより早く棄却/通過できるか。
4. FPGA見積もりに変換したとき、ソフトウェア上の計算削減が電力削減として残るか。
